## The rule that caused most confusion

`sdbd` serves **one loopback client**. The app probe and a Mac sdb session
cannot be upstream together. Close `sdb` before `/cmd`; close `/cmd` before
`sdb`. Full detail: `docs/sdb-relay.md`.

## Other traps hit today

- `sh file` fails under UEP; use `sh -c "$(cat file)"`.
- `sh -c "$(cat bridge.sh)" stop` misses the subcommand; pass `sh` as `$0`:
  `sh -c "$(cat f)" sh stop`.
- A token rewrite needs a bridge stop/start; the token is read once.
- `tizen install` resets both DB flags. Re-arm with
  `sh -c "$(cat /opt/usr/share/tvroot/app-boot)"`.
- Launching `.Main` via `POST :8001/api/v2/applications/tiz0wnprob.Main`
  starts the service too when the app is down.

### What exists

- `home.html`: fixture-only home with a single-row carousel, three copied sets,

- `ui/tokens.css` + `docs/ui-system.md`: the extracted system.
- `tests/render/carousel.py`: Playwright harness at 1080p and 4K, screenshots
  in `docs/shots/`. On the host it reports 18 vw tiles, 2 vw gaps, centred
  focus, no scroll and a one-gap seam.

### Likely root cause, not yet fixed

**Flex `gap` is not supported in Chromium 69** (it shipped in Chromium 84, grid
gap is older). `.shelf` and `.set` both rely on `gap: 2vw`; on the TV those
gaps are ignored, so tiles sit edge to edge and can overlap once anything else
adds width. The harness runs a modern Chromium, so it cannot see the fault.

Fix direction: replace flex gap with `margin-right: 2vw` on cards (and account
for it in the offset math / last card), or a `padding`-based spacer. Then rerun
the harness and, critically, check it on the TV. A second, cheap device check
is to render the same page in the TV's own browser engine if possible.

### Other UI traps hit

- remote keys need `hwkey-event="enable"` and explicit registration; without
  both, nothing reaches the page
- focus() scrolls the document unless `preventScroll` is passed
- `tizen.tvwindow` needs the `tv.window` privilege; whether source composition
  works is unverified
- fixed px sizes break on 4K; the root size now derives from `vw`
